Frequently Asked

Questions MSPs always ask.

Does this replace the C3PAO assessment?
No — nothing does. A C3PAO (Certified Third-Party Assessment Organization) is required by DoD to perform the formal assessment. What the platform does is prepare your client for that assessment: all 110 controls tracked, every piece of evidence assessed against its specific objectives, and a complete audit package ready to hand over. Claude's pre-assessment typically catches gaps that would otherwise cause assessor findings.
How accurate are Claude's assessments?
Claude assesses each artifact against the specific NIST assessment objectives, using the CMMC Information Institute's acceptable proof guidance as context. Every verdict includes rationale, confidence score, and a gap list. MSP admins can override any verdict with documented reasoning — the override is logged to the activity trail for C3PAO review. In practice, verdicts are used as a first-pass; final sign-off is always human.
Is CUI data safe on the platform?
Multi-tenant isolation is enforced at the PostgreSQL row level via Hasura permissions — a client_user from Org A cannot query data from Org B regardless of what their token says. Artifacts live in MinIO with org-scoped bucket paths. TLS end-to-end via Traefik with wildcard certs. For FedRAMP-level deployments, the entire stack runs on a single VM you control — we can deploy to your AWS GovCloud / Azure Government environment if required.
We already use Drata / Vanta. Why switch?
Drata and Vanta are SOC 2 tools. They've mapped 800-171 as a framework, but they don't enforce DoD scoring rules (the SSP −203 gate), don't do FAR & Above phasing, and don't generate an actual C3PAO audit package — they generate a SOC 2 evidence binder. This platform is purpose-built for CMMC Level 2 and nothing else. Most MSPs serving DIB keep their existing tool for SOC 2 clients and add this one for CMMC clients.
How long does onboarding actually take?
For the MSP: under 30 minutes to spin up a new client org, including scoping config and client admin invite. For the client: day-one SSP interview (45 min) + integration connections (30 min per provider) + harvester run (10 min). By the end of day 3, the client typically has 40+ controls auto-satisfied and a clear action list for the rest.
What if our client uses tools outside the 6 integrations?
Manual upload is always available. Beyond that, the Windows and Linux harvester scripts collect evidence from any endpoint — firewall rules, GPO exports, audit policies, patch status, etc. — regardless of what management tooling the client uses. For everything else, the AI Copilot helps contributors identify exactly what screenshot or export will satisfy a given control.
Do we own the data? Can we export it?
Yes. Every artifact is yours. The C3PAO audit package export is a single ZIP with SSP PDF, POA&M PDF, every artifact file, a SHA-256 manifest, and a control-to-evidence map. You can generate it any time, and you can extract everything via the API if you ever want to leave the platform. No vendor lock-in clauses.
