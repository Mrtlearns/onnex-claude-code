RAGv1 — Technical Architecture

RAGv1 is Onnex's internal Retrieval-Augmented Generation platform. It is built by Mr. T as a proof-of-concept document intelligence system and serves as the foundation for the AI-OS document module. RAGv1 is a full-stack application combining a React frontend with Supabase backend services and multiple Deno-based edge functions.

System Architecture

RAGv1 follows a multi-tenant architecture. Users create projects, upload documents, and interact with document content through a conversational AI interface. Each project maintains isolated data including documents, embeddings, entities, and chat sessions.

The frontend is built with React 18 and TypeScript, using Vite as the build tool and shadcn/ui for component styling. The application routes are managed by React Router and state is coordinated through TanStack Query and React Context.

Backend Services (Supabase)

Supabase provides the foundational backend services. PostgreSQL with the pgvector extension stores all relational data including document chunks and 1536-dimensional vector embeddings. Supabase Auth handles user authentication with JWT tokens. Supabase Storage manages document file uploads in the poc-ragv1-docs bucket.

Three core Deno edge functions power the pipeline: ragv1-process-document handles document ingestion, chunking, embedding generation, and entity extraction. ragv1-chat provides streaming conversational AI with RAG retrieval. ragv1-eval evaluates retrieval quality using faithfulness, relevance, and groundedness metrics.

Document Processing Pipeline

When a user uploads a document, RAGv1 executes a multi-stage processing pipeline:

Text extraction handles PDF files using pdf-parse with Gemini Vision as fallback. DOCX files are processed using the mammoth library. PPTX and XLSX files use officeparser and xlsx respectively.

Text is tokenized and split into overlapping chunks of approximately 1000 tokens each. Each chunk is embedded using Google Gemini's gemini-embedding-001 model, which produces 1536-dimensional vectors stored in pgvector.

Entity extraction uses Gemini to identify named entities from the document text, including organizations, persons, products, technologies, locations, dates, concepts, and events. Relation extraction then identifies semantic relationships between extracted entities, building a knowledge graph stored in the entities and entity_relations tables.

Retrieval Strategy

RAGv1 implements hybrid retrieval combining vector similarity search and BM25 full-text search using Reciprocal Rank Fusion (RRF). The match_chunks_hybrid PostgreSQL function executes both search strategies and merges results using RRF scoring. An optional re-ranking step uses Gemini to score chunk relevance against the query, selecting the top-k most relevant chunks.

The chat pipeline uses a ReAct agentic loop: retrieve chunks, assess sufficiency, reformulate the query if needed, and retrieve again up to three rounds before generating a final response. Graph-based retrieval supplements vector search by finding document chunks connected through entity relationships.

Deployment

RAGv1 is deployed on poc-backend, a self-hosted Supabase instance running on a Proxmox homelab server. The frontend is served by an nginx container. Deno edge functions run on the Supabase edge runtime. Network access is managed through Tailscale for secure remote connectivity.
